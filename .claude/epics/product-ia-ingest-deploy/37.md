# Task: Review states idle loading error severities

## Why

The report surface mixes fleet progress, live errors, and verdict chips without first-class states. Judges need to instantly read idle, loading, error, Critical, High, and Clear.

## Description

Make the session Report UI (`Dashboard.jsx` report / `/sessions/:id`) drive distinct states from real data:

- **idle** — no session selected / nothing analyzed yet
- **loading** — analyze in flight
- **error** — Gateway/server failure (honest; no fake pass)
- **Critical / High / Clear** — from `headlineVerdict` / stored findings (`sess_tcpa_04`, `sess_late_01`, `sess_clean_01`)

Use ComplyLine tokens only (paper/ink/navy). No Vanta purple, no incident.io orange.

## Acceptance Criteria

- [ ] Idle, loading, error, Critical, High, Clear are visually and accessibly distinct.
- [ ] States are data-driven from findings / request lifecycle, not hardcoded for the demo.
- [ ] `sess_tcpa_04` shows Critical, `sess_late_01` High, `sess_clean_01` Clear.
- [ ] Error does not look like Clear.
