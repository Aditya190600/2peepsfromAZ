# Task: Deploy sample MP3s and warm-cache

## Why

Hackathon submission requires a live demo (Vercel, Replit, or Streamlit). Sample MP3s are gitignored (`*.mp3`), so clones and hosts have no playback. A cold Gateway burst on first judge visit recreates Session A's error-card problem unless the 12 Northstar sessions are warm-cached on boot.

## Description

Deploy the app to Vercel or Replit. Make sample MP3s available to clones (commit demo samples and/or document `scripts/generate-sample-audio.py` as a required post-clone step; prefer files the deploy actually serves). On server boot, analyze the 12-session program once and cache results in memory so Home/KPIs do not fire a cold 12-way Gateway run. If cache fails, show error/loading — do not fake 83%.

## Acceptance Criteria

- [ ] Public demo URL on Vercel or Replit (or Streamlit if that is the only path that works).
- [ ] Sample MP3s play on `/try` for the playable fixtures after clone/deploy.
- [ ] Server boot warm-caches the **12** Northstar sessions.
- [ ] First Home visit after boot does not produce Gateway error cards from a cold 12-run.
- [ ] Cache miss/failure is honest (error/loading), not a fake 83% widget.
- [ ] README documents deploy + sample audio generate.

## Technical Details

### Key files
- `server/index.js` (boot cache)
- `server/checks/analyze.js` / `llmGateway.js` (reuse mutex)
- `client/src/sampleSessions.js`
- `scripts/generate-sample-audio.py`
- `README.md`
- `.gitignore` (only if committing `client/public/samples/*.mp3` for the demo set)

### Done when
A clean clone + the public URL can show the 12-session home and play samples without a first-visit 429 storm.
