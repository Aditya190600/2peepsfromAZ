# Task: LLM mutex and NER scope

## Why

A cold 12-session demo still 429s the AssemblyAI LLM Gateway because `analyze.js` runs disclosure + PII NER in `Promise.all` and the fleet client adds more concurrency. `llmGateway.js` retries 429s but does not serialize in-flight calls. NER also flags spoken org names like "Acme Support", which poisons pass/flag counts for an otherwise clean greeting.

## Description

Add a process-wide mutex (async queue) in `server/checks/llmGateway.js` so only one Gateway HTTP call is in flight. Keep `analyze.js` composition as-is. Narrow NER in `server/checks/piiScan.js` so organization/support-desk names in greetings are not PII findings. Tests must prove both.

## Acceptance Criteria

- [ ] At most one in-flight `fetch` to LLM Gateway from `callLlmGateway` (queue subsequent callers).
- [ ] `analyze.js` `Promise.all` still works; mutex is inside the gateway client.
- [ ] NER does **not** flag `"Acme Support"` (or equivalent org/support greeting names).
- [ ] NER still flags person names, emails, phones, and street addresses when present.
- [ ] Cold 12-session run has **zero** error cards (`status: error` / "Unable to run" from Gateway).
- [ ] Tests cover mutex serialization and the Acme Support non-flag.

## Technical Details

### Key files
- `server/checks/llmGateway.js`
- `server/checks/piiScan.js` (`NER_SYSTEM_PROMPT` / post-filter)
- `server/checks/analyze.js` (compose only; do not fake results)
- `server/checks/analyze.test.js` (extend) and/or new `llmGateway`/`piiScan` tests
- Client `mapWithConcurrency` in `Dashboard.jsx` is **not** a substitute; leave it unless it still over-fires 12 POSTs in a way that bypasses the server mutex (each POST is one analyze; mutex serializes the two Gateway calls inside each analyze, and should also serialize across concurrent analyzes).

### Done when
Mutex + NER tests pass (`cd server && npm test`); a scripted or manual cold 12-run shows no Gateway error cards.
