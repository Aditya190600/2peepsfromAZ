# Task: Reopenable reports from history

## Why

`reportHistory.js` currently stores label, sessionId, and verdict only (`Dashboard.jsx` `recordHistory`). History is a dead list — clicking a row cannot show the Report UI without re-analyzing (and 429ing). Judges need to click a session and see the same findings.

## Description

Persist full findings (and whatever session metadata the Report UI needs) in `reportHistory.js`. History and session-list clicks open that stored Report UI. Add route `/sessions/:sessionId` in `App.jsx` (or equivalent inside `Dashboard.jsx` if routes are not split yet). Do not re-call Gateway on reopen.

## Acceptance Criteria

- [ ] `saveHistoryEntry` / load path stores **findings** (not just verdict metadata).
- [ ] Clicking a History row opens the same Report UI as the original run.
- [ ] Clicking a session in the 12-session list opens that session's stored report when present.
- [ ] Route `/sessions/:sessionId` works (deep-link / refresh if the hand-rolled router allows).
- [ ] Reopen does **not** call `/v1/analyze-session` again.
- [ ] Missing session shows a clear empty/error state, not a crash.

## Technical Details

### Key files
- `client/src/reportHistory.js`
- `client/src/History.jsx`
- `client/src/Dashboard.jsx` (report UI + `recordHistory`)
- `client/src/App.jsx`

### Done when
History/session click restores the identical findings view from localStorage.
